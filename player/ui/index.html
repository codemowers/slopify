Ubuntu: discover AirPlay speakers

        
On a PipeWire desktop, run once per audio session, without sudo:

        
pactl load-module module-raop-discover
pactl list short sinks

        
        
Select the advertised speaker in Ubuntu Sound settings. Move already-running applications with pavucontrol if needed. Select the AirPlay source in this speaker’s Sources section, or enable Recent/Priority selection.

        
Persistent AirPlay discovery — this user

        
On Ubuntu 24.04/26.04 with PipeWire, load RAOP discovery after login. Restarting audio briefly interrupts playback.

        
mkdir -p ~/.config/pipewire/pipewire-pulse.conf.d
cat > ~/.config/pipewire/pipewire-pulse.conf.d/30-airplay-discovery.conf <<'EOF'
pulse.cmd = [ { cmd = "load-module" args = "module-raop-discover" } ]
EOF
systemctl --user restart pipewire-pulse

        
        
Persistent AirPlay discovery — system-wide

        
Use this instead of the per-user snippet to enable discovery for every user's audio session.

        
sudo mkdir -p /etc/pipewire/pipewire-pulse.conf.d
sudo tee /etc/pipewire/pipewire-pulse.conf.d/30-airplay-discovery.conf > /dev/null <<'EOF'
pulse.cmd = [ { cmd = "load-module" args = "module-raop-discover" } ]
EOF
systemctl --user restart pipewire-pulse

        
        
Choose one scope. The restart affects your current user; other users pick up the setting at their next audio-session start. To disable persistent AirPlay discovery, remove 30-airplay-discovery.conf from the chosen location and restart that user's PipeWire-Pulse session.

        
macOS, iPhone and iPad

        
Open Control Centre, choose the audio output/AirPlay selector and select this speaker’s advertised name. On macOS, the output is also available in Sound settings. The speaker receives AirPlay 1 audio: 16-bit 44.1 kHz ALAC, without AirPlay 2 multi-room grouping.

        
Apple devices need AirPlay encryption, which is off on this speaker. On OpenWrt, enable it in the Slopify player settings; elsewhere start the player with -raop-key.

        
If the speaker is missing

        
Check that the AirPlay receiver and mDNS discovery are running on the speaker and that the LAN/VPN permits multicast DNS (UDP 5353) and the receiver’s audio ports. If module loading fails, check that the laptop’s PipeWire installation includes its RAOP discovery module. To remove temporary discovery, find module-raop-discover with pactl list short modules, then run pactl unload-module MODULE_ID.

Manual IP tunnel — including across subnets

        
mDNS normally stays on one network segment. Across a routed subnet or VPN, use this explicit address instead; the speaker’s TCP port 4713 must be reachable. These commands use the address you opened this page with.

        
Run in your laptop terminal. Use sudo only for installing the tools. Add this output once per audio session.

        
pactl unload-module module-tunnel-sink 2>/dev/null
pactl load-module module-tunnel-sink server=tcp:SPEAKER_IP:4713 sink=SPEAKER_DEVICE sink_name=SPEAKER_SINK "sink_properties='device.description=\"SPEAKER_NAME via PulseAudio\"'"
pactl set-default-sink SPEAKER_SINK

Set up Multicast RTP — PipeWire

        
This setup creates a persistent laptop output labelled with its multicast group. The group uses two bytes of a Slopify-prefixed machine-ID hash, so it stays stable across reboots without publishing the machine ID. Audio and SAP discovery follow the current route rather than a fixed interface, so docking, undocking or changing networks needs no new setup. Both modules are optional: if one cannot start, laptop audio still works without the multicast output. Multicast uses its own 30-slopify-rtp.conf file; it coexists with PulseAudio discovery and fixed unicast configurations.

        
Rerunning setup replaces this configuration with the same derived group. Restarting PipeWire-Pulse briefly interrupts laptop audio. Afterward, select the multicast output in Sound settings and move already-playing applications if needed.

        
(
set -eu
grep -Eq '^[0-9a-fA-F]{32}$' /etc/machine-id || { echo 'A valid /etc/machine-id is required.' >&2; exit 1; }
rtp_hash=$( { printf 'slopify-rtp-v1:'; cat /etc/machine-id; } | sha256sum | cut -c1-4)
rtp_a=$(printf '%s' "$rtp_hash" | cut -c1-2)
rtp_b=$(printf '%s' "$rtp_hash" | cut -c3-4)
rtp_group="239.192.$((0x$rtp_a)).$((0x$rtp_b))"
mkdir -p ~/.config/pipewire/pipewire-pulse.conf.d
# Substitute only the group; keep configuration quoting intact.
sed -e "s/RTP_GROUP/$rtp_group/g" > ~/.config/pipewire/pipewire-pulse.conf.d/30-slopify-rtp.conf <<'EOF'
context.modules = [
  { name = libpipewire-module-rtp-sink
    flags = [ nofail ]
    args = {
      destination.ip = "RTP_GROUP"
      destination.port = 5004
      net.ttl = 1
      audio.format = S16BE
      audio.rate = 48000
      audio.channels = 2
      audio.position = [ FL FR ]
      stream.props = {
        channelmix.lock-volumes = true
        node.name = slopify_rtp
        node.description = "Multicast RTP [RTP_GROUP]"
        media.class = Audio/Sink
        node.virtual = true
      }
    }
  }
  { name = libpipewire-module-rtp-sap
    flags = [ nofail ]
    args = {
      sap.ip = "224.0.0.56"
      net.ttl = 1
      stream.rules = [
        { matches = [ { node.name = slopify_rtp } ]
          actions = { announce-stream = {} }
        }
      ]
    }
  }
]
EOF
systemctl --user reset-failed pipewire-pulse 2>/dev/null || true
systemctl --user restart pipewire-pulse
printf 'Multicast RTP: %s:5004\n' "$rtp_group"
)

        
        
Remove multicast output

        
Switch to another laptop output, then remove the startup file and restart PipeWire-Pulse:

        
rm -f ~/.config/pipewire/pipewire-pulse.conf.d/30-slopify-rtp.conf
systemctl --user reset-failed pipewire-pulse 2>/dev/null || true
systemctl --user restart pipewire-pulse

        
        
Connection details

        
The output uses stereo 48 kHz, 16-bit PCM. Its volume and mute are locked at unity; adjust listening volume on each speaker. Application volume controls still apply. On this speaker, select the RTP source if another source is pinned, or enable Recent/Priority. Every compatible receiver joining this group can receive it.

        
SAP announcements use 224.0.0.56:9875; audio uses the derived group on UDP 5004. Both follow the kernel's route for each packet, normally the current default route; this can be a VPN if it owns the default route. To pin an interface, add local.ifname to both modules in the saved file (PipeWire then skips the output while that interface is absent); to override the group, edit destination.ip and its bracketed output label. Restart PipeWire-Pulse after editing.

        
Cloned machine IDs and hash collisions can share groups; Slopify keeps different sender IPs separately selectable. Audio is unencrypted and unauthenticated. No mDNS discovery or speaker multicast sender is required.
