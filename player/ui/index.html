Ubuntu: discover AirPlay speakers

On a PipeWire desktop, run once per audio session, without sudo:

pactl load-module module-raop-discover
pactl list short sinks

Select the advertised speaker in Ubuntu Sound settings. Move already-running applications with pavucontrol if needed. Select the AirPlay source in this speaker’s Sources section, or enable Recent/Priority selection.

Persistent AirPlay discovery — this user

On Ubuntu 24.04/26.04 with PipeWire, load RAOP discovery after login. Restarting audio briefly interrupts playback.

mkdir -p ~/.config/pipewire/pipewire-pulse.conf.d
cat > ~/.config/pipewire/pipewire-pulse.conf.d/30-airplay-discovery.conf <<'EOF'
pulse.cmd = [ { cmd = "load-module" args = "module-raop-discover" } ]
EOF
systemctl --user restart pipewire-pulse

Persistent AirPlay discovery — system-wide

Use this instead of the per-user snippet to enable discovery for every user's audio session.

sudo mkdir -p /etc/pipewire/pipewire-pulse.conf.d
sudo tee /etc/pipewire/pipewire-pulse.conf.d/30-airplay-discovery.conf > /dev/null <<'EOF'
pulse.cmd = [ { cmd = "load-module" args = "module-raop-discover" } ]
EOF
systemctl --user restart pipewire-pulse

Choose one scope. The restart affects your current user; other users pick up the setting at their next audio-session start. To disable persistent AirPlay discovery, remove 30-airplay-discovery.conf from the chosen location and restart that user's PipeWire-Pulse session.

macOS, iPhone and iPad

Open Control Centre, choose the audio output/AirPlay selector and select this speaker’s advertised name. On macOS, the output is also available in Sound settings.

If the speaker is missing

Check that Shairport and mDNS discovery are running on the speaker and that the LAN/VPN permits multicast DNS (UDP 5353) and the receiver’s audio ports. If module loading fails, check that the laptop’s PipeWire installation includes its RAOP discovery module. To remove temporary discovery, find module-raop-discover with pactl list short modules, then run pactl unload-module MODULE_ID.

Automatic discovery on the same LAN

This speaker advertises its hostname as a Pulse sink over mDNS. Enable discovery on your Ubuntu laptop, then choose the advertised speaker in Sound settings:

pactl unload-module module-zeroconf-discover 2>/dev/null
pactl load-module module-zeroconf-discover
pactl list short sinks

Persistent discovery — this user

To load discovery after login on an Ubuntu 24.04/26.04 PipeWire desktop, save the configuration below. Restarting desktop audio interrupts playback. Use discovery or the manual tunnel below to avoid duplicate outputs.

mkdir -p ~/.config/pipewire/pipewire-pulse.conf.d
cat > ~/.config/pipewire/pipewire-pulse.conf.d/30-speaker-discovery.conf <<'EOF'
pulse.cmd = [ { cmd = "load-module" args = "module-zeroconf-discover" } ]
EOF
systemctl --user restart pipewire-pulse

Persistent discovery — system-wide

To enable discovery for every user on this laptop, install the snippet under /etc instead. Each user still runs their own PipeWire-Pulse session. Choose either the per-user or system-wide configuration; do not install both.

sudo mkdir -p /etc/pipewire/pipewire-pulse.conf.d
sudo tee /etc/pipewire/pipewire-pulse.conf.d/30-speaker-discovery.conf > /dev/null <<'EOF'
pulse.cmd = [ { cmd = "load-module" args = "module-zeroconf-discover" } ]
EOF
systemctl --user restart pipewire-pulse
pactl list short sinks

The restart applies to your current user and briefly interrupts audio. Other users pick up the setting at their next audio-session start, or can run the same restart command themselves without sudo. To disable persistent discovery, remove the configuration file from the location you chose and restart that user's PipeWire-Pulse session.

Manual IP tunnel — including across subnets

mDNS normally stays on one network segment. Across a routed subnet or VPN, use this explicit address instead; the speaker’s TCP port 4713 must be reachable. These commands use the address you opened this page with.

Run in your laptop terminal. Use sudo only for installing the tools. Add this output once per audio session.

pactl unload-module module-tunnel-sink 2>/dev/null
pactl load-module module-tunnel-sink server=tcp:SPEAKER_IP:4713 sink=SPEAKER_DEVICE sink_name=SPEAKER_SINK "sink_properties='device.description=\"SPEAKER_NAME\"'"
pactl set-default-sink SPEAKER_SINK

One application, skipping the laptop’s audio server

Applications using PulseAudio can connect to the speaker directly. The stream is not mixed: a second application from this laptop replaces the first, and it has no microphone. Quit Chrome completely first, or this only opens a window in the running one.

PULSE_SERVER=tcp:SPEAKER_IP:4713 google-chrome

2. Select Slopify

Choose the speaker’s advertised hostname under Output in Ubuntu Sound settings. Already-running applications may need to be moved separately with pavucontrol. When source control is enabled, select the laptop under Sources or choose Recent or Priority for automatic switching. Otherwise pause the speaker’s Slopify queue first.

When the speaker’s hardware-volume bridge is enabled, laptop output volume controls the speaker within its configured limits. New connections inherit the current speaker level; knob and web volume changes update the laptop control. Mute applies to the laptop stream.

3. Keep it after login (optional)

For a PipeWire desktop, save this startup configuration after the temporary output works. Restarting desktop audio interrupts playback; the temporary output is replaced on restart.

mkdir -p ~/.config/pipewire/pipewire-pulse.conf.d
cat > ~/.config/pipewire/pipewire-pulse.conf.d/30-slopify.conf <<'EOF'
pulse.cmd = [
  { cmd = "load-module"
    args = "module-tunnel-sink server=tcp:SPEAKER_IP:4713 sink=SPEAKER_DEVICE sink_name=SPEAKER_SINK sink_properties='device.description=\"SPEAKER_NAME\"'"
  }
]
EOF
systemctl --user restart pipewire-pulse

Connection checks and removal

pactl info
pactl --server=tcp:SPEAKER_IP:4713 list short sinks
pactl list short modules

A connection failure usually means the address, speaker receiver or network needs checking. To remove the temporary output, select your laptop speakers, find the module-tunnel-sink ID in the module list, then run pactl unload-module MODULE_ID. For a persistent output, also remove its 30-slopify.conf startup file.
